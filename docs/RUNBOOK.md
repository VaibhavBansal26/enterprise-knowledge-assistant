# Runbook

Audience: whoever deploys and operates this. Commands assume the production-shaped stack in `docker-compose.prod.yml`; adapt the same steps to your platform (Render, Fly.io, Azure Container Apps, Kubernetes).

> Status: the stack is verified locally (build, migrate, k6, Playwright). It has **not** been deployed to a hosted platform from this repository yet, so the platform steps below are a procedure to follow, not a record of a live deployment.

## Components
| Image | Built from | Notes |
|---|---|---|
| `kb-api` | `src/Api/Dockerfile` target `runtime` | Port 8080, non-root, stateless except uploaded blobs on `/data/blobs` |
| `kb-migrator` | same file, target `migrator` | Self-contained EF bundle; runs once per release and exits |
| `kb-web` | `web/Dockerfile` | nginx on 8080: static SPA, proxies `/api`, `/hubs`, `/health` to the API |

Dependencies: PostgreSQL 17 with the `vector` extension, Redis 7, an OIDC provider, and optionally an LLM key, an OTLP backend and Sentry.

## Configuration
Secrets come from the platform's secret store as environment variables, never from files in the repo.

| Variable | Purpose |
|---|---|
| `Database__ConnectionString` | Postgres connection (app role) |
| `Database__MigrateOnStartup` | `false` in production; migrations run as their own step |
| `Redis__ConnectionString` | Redis |
| `Auth__Authority`, `Auth__MetadataAddress` | Token issuer (must equal the `iss` claim) and where to fetch keys |
| `Auth__RequireHttpsMetadata` | `true` for any real HTTPS provider |
| `Llm__Provider`, `Llm__Anthropic__ApiKey` | `anthropic` for real answers; default is the offline stand-in |
| `Usage__DefaultMonthlyCostLimitUsd` | Per-workspace monthly quota (0 disables) |
| `Sentry__Dsn`, `Telemetry__OtlpEndpoint` | Error tracking and traces/metrics; empty disables |
| `ASPNETCORE_FORWARDEDHEADERS_ENABLED` | `true` behind a proxy or TLS terminator |
| Web build args `VITE_OIDC_AUTHORITY`, `VITE_OIDC_CLIENT_ID` | Baked into the SPA at build time |

Invalid configuration fails at startup with a message naming the field (for example, a quota outside its allowed range), so a bad deploy never half-starts.

## Health
- `GET /health/live` — process is up (use for liveness).
- `GET /health/ready` — Postgres and Redis reachable (use for readiness and as the deploy gate).

## Deploy
On Render, follow [DEPLOY-FREE.md](DEPLOY-FREE.md) (free) or [DEPLOY-RENDER.md](DEPLOY-RENDER.md) (paid, with Keycloak); the generic procedure is below.

1. Build and tag images with the git SHA: `docker build -f src/Api/Dockerfile --target runtime -t kb-api:$SHA .` (likewise `--target migrator`, and `docker build -t kb-web:$SHA web`). Push them to your registry.
2. Take a database backup (see below).
3. Run the migrator against production: `docker run --rm kb-migrator:$SHA --connection "<connection string>"`. It must exit 0. If it fails, stop: the old version is still serving.
4. Roll out `kb-api:$SHA`, wait for `/health/ready`, then roll out `kb-web:$SHA`.
5. Smoke test: sign in, ask a question, open the Operations page.

Local equivalent: `docker compose -f docker-compose.prod.yml --env-file .env up -d --build` (the `migrate` service gates the API automatically).

## Rollback
- **Code:** redeploy the previous image tags (`kb-api:$PREV`, `kb-web:$PREV`). Migrations are written expand/contract ([ADR 0005](adr/0005-migrations-as-a-release-step.md)), so the previous version runs against the newer schema. Do not run the migrator again.
- **Data / bad migration:** restore the pre-deploy backup into a new database, point `Database__ConnectionString` at it, and redeploy the previous tags. Expect to lose writes made after the backup.
- **Embedding model change:** after upgrading across an embedding model id (for example `hashing-v1` to `hashing-v2`), reprocess documents (`POST /api/v1/workspaces/{id}/documents/{docId}/reprocess`); rolling back requires reprocessing again.

## Backups
Back up Postgres (`pg_dump -Fc` or the platform's point-in-time recovery) and the blob volume together; chunks and embeddings can be regenerated by reprocessing, but uploaded originals cannot. Test a restore before relying on it.

## Operating notes and known limits
- **Uploads are stored on local disk** (`Storage__RootPath`). Run one API replica per volume, or mount shared storage; object storage is not implemented. SignalR already uses the Redis backplane, so only blob storage blocks scale-out.
- **Rate limits** are per user via Redis (`RateLimiting__*`, `Chat__RequestsPerMinute`); load tests need `tests/load/docker-compose.loadtest.yml`.
- **nginx re-resolves the API every 5 seconds** (`DNS_RESOLVER` (auto-detected from resolv.conf), `API_UPSTREAM`), so replacing the API container does not need a web restart. Override `DNS_RESOLVER` only if auto-detection is wrong.

## Incidents
| Symptom | Check | Action |
|---|---|---|
| Users get 502 | `/health/ready` on the API; `docker compose logs api` | API crash at startup is usually config validation: fix the named field |
| Everyone gets 401 | Token `iss` vs `Auth__Authority`; API can reach `Auth__MetadataAddress` | Align the issuer URL; the browser and API must agree on it |
| 429 on chat | Per-user limit or workspace quota | Check Operations page; raise `Usage__DefaultMonthlyCostLimitUsd` or `PUT /api/v1/admin/quota` |
| Documents stuck in Pending/Processing | `select id, type, attempts, last_error, dead_at from outbox_messages where processed_at is null order by created_at;` | Leases expire and retry with backoff. Dead-lettered jobs have `dead_at` set; fix the cause, then `POST .../reprocess` |
| Answers are slow or failing | Aspire/OTLP traces (`chat.ask` and its child spans); `kb.llm.*` metrics | An open LLM circuit makes chat fail fast until it recovers; check provider status and key |
| Eval gate failed in CI | Download the `eval-results` artifact | A real regression: fix it. A deliberate change: update `evals/baseline.json` in the same PR |
| Cost looks wrong | Operations page; `usage_ledger` | Prices are estimates from `Pricing:Models`; unknown models use a high fallback price |

## Load and end-to-end checks
- k6: see the header of `tests/load/smoke.js`. Thresholds: read p95 < 300 ms, chat p95 < 2 s, error rate < 1%. Chat numbers use the offline stand-in and the semantic cache, so they understate a real model's latency; rerun with `Llm__Provider=anthropic` for a realistic figure.
- Playwright: `cd tests/e2e && npm ci && npx playwright install chromium && npx playwright test` (stack must be running; `BASE_URL` defaults to `http://localhost:8088`).
